# 节点 ID 体系规格（全站唯一编号）

状态：**设计已确认 Kevin 2026-09-16 · 待实施**
关联：`docs/data-model.md`、`docs/clan-tree.spec.md`、`docs/founder-attach.spec.md`、`docs/PENDING_DEPLOY.md`

## 1. 目标（Kevin 原话口径）

> 全数据库范围内（含中华世本与各祖谱）的节点 ID **唯一**，通过一个 ID 即可精确锁定全站某一个节点；**一劳永逸**。

## 2. 两层标识

| 层 | 字段 | 唯一性 | 可变性 | 用途 |
|---|---|---|---|---|
| **机器主键** | `handle`（24 位随机 hex） | 全站唯一（随机生成） | **永不变**（改父、跨树迁移、改名都不动） | 所有内部引用、外树指针（`external_person_handle`）、详情文档键 `tree_id:handle` |
| **人读编号** | `gramps_id` | **全站唯一**（本文档规定） | **永不变**（跨树迁移不再重编号） | 界面显示、人工引用、跨树定位、用户输入 |

- 编号格式：人员 `I` + 6 位十进（`I000052`）；家族记录 `F` + 6 位（`F000012`）。显示时可省略前缀（`000052`）。
- 规则：**人读编号一经分配，终身不变**；跨树迁移、改父、改名、改称号都不改编号（这与当前"迁移即重编"的行为相反，是本规格的关键变更）。

## 3. 全局计数器

- 单一计数器，持久化在集合 `jiazu_id_seq`（本地 `migrate-output/collections/jiazu_id_seq.json`）：
  `{ _id: 'person', next: <number> }` / `{ _id: 'family', next: <number> }`
- 铸号走**原子递增**：云端用 `db.command.inc`，本地走 `store` 的写锁；并发安全，绝不重号。
- 每个新节点/新家族在创建时领号；已存在节点在迁移时统一领号。

## 4. 迁移方案（一次性）

1. **中华世本（zhonghua）现有编号原样保留** —— 它是被文档与用户记忆引用最多的一棵树（如 `0052 风伏羲`、`0101`…），且其编号在树内唯一。
2. 计数器初值 = `max(zhonghua 现有编号) + 1`。
3. **其它所有树（祖谱 + 普通树）逐树重编号**，顺序固定（tree_id 字典序 → 原编号升序），保证可重放。
4. 产出 **映射表** `migrate-output/id-migration.json`：`{ tree_id: { 旧编号: 新编号 } }`；同时在节点详情文档里写 `legacy_gramps_id`（只读留痕）。
5. 解析器过渡期**同时接受旧号**（在已知树上下文时），并在日志/界面提示"该编号已迁移为 X"。

## 5. 统一解析器（收益最大的部分）

后端提供 `resolveNode(ref, treeId?)` → `{ tree_id, handle, gramps_id }`，接受：

| 输入 | 示例 | 说明 |
|---|---|---|
| 全局编号 | `I000052` / `000052` | 全站唯一定位，**不需要指定树** |
| handle | `10400594c54f5203f61bf4fa4b20` | 精确锁定 |
| 树内旧号（过渡期） | `0052` + `tree_id` | 兼容历史输入 |

接入**所有"选节点"入口**：改父、删除、认祖、嫁娶、挂载、搜索。由此：
- 撤销"目标家族树（跨树迁移）"这类多余选择步骤（填全局编号即自动识别所属树）；
- 跨树操作不再需要"先选树再填号"两步。

## 6. 与既有机制的关系

- `handle` 的地位不变（仍是不可变主键）；本规格只把 `gramps_id` 从"树内序号"升级为"全站编号"。
- 树内"局部序号"不再作为标识；若界面需要，只作为**派生展示值**（不参与识别、不参与输入）。
- `external_*` 指针仍全部用 `handle`，因此**本次重编号不影响任何跨树关系**（婚姻/始祖挂载/祖谱链）。

## 7. 实施清单

- 后端：`lib/id-seq.js`（计数器 + 铸号，云端 `inc` / 本地锁）；`lib/store.js` 暴露 `nextPersonId()/nextFamilyId()`；`lib/id-resolve.js`（统一解析器）；所有创建路径改为铸全局号；`resolveNode` 接入各路由。
- 迁移脚本：`scripts/migrate-global-ids.mjs`（幂等、可重放、产出映射表 + 写 `legacy_gramps_id`；先跑 `/tmp` 副本校验再上真源）。
- 前端：`format.ts` 的 `personIdDisplay` 适配 6 位；档案页"编号"行 + 一键复制；所有"编号"输入框提示统一为「全局编号（如 000052）或 handle」；撤销迁移目标树选择器。
- 文档：本文件 + `docs/data-model.md` 同步；`docs/PENDING_DEPLOY.md` 追加计数器集合与迁移脚本。
- 测试：计数器原子性与唯一性、并发铸号不重号、解析器全形式、迁移脚本幂等与真源 md5、跨树迁移后**编号不变**。

## 8. 风险与代价（已知）

1. 除 zhonghua 外，所有树的节点编号会变 → 用户既有引用（截图/笔记）失效；用映射表 + `legacy_gramps_id` 兜底。
2. 云端需要 `jiazu_id_seq` 集合与原子操作；迁移脚本必须先在副本上验证。
3. 任何硬编码编号的测试夹具/脚本需同步更新。
4. 跨树迁移的语义变化：**不再重编号**（改为"换树不换号"），需同步修正现有实现与测试（当前实现会按目标树重分配编号）。
