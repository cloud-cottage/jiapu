### 1-3 生卒存量形态实测底账（**只读复现 · 本册实测**）—— ① 为什么必须保留自由文本

**复现命令**（19 棵树；`migrate-output/trees/*.json` 的 `people.<handle>.birth_date` / `death_date`）：

```bash
cd /Users/kevin/bistro/jiapu
python3 -c "
import json,glob,re
iso=yr=ns=0; vals={}
for p in sorted(glob.glob('migrate-output/trees/*.json')):
    d=json.load(open(p))
    for h,v in d.get('people',{}).items():
        if not isinstance(v,dict): continue
        for k in ('birth_date','death_date'):
            s=str(v.get(k) or '').strip()
            if not s: continue
            if re.fullmatch(r'\d{4}-\d{2}-\d{2}',s): iso+=1
            elif re.fullmatch(r'\d{4}',s): yr+=1
            else: ns+=1; vals[s]=vals.get(s,0)+1
print('iso',iso,'year_only',yr,'nonstd_occ',ns,'nonstd_distinct',len(vals))
print(sorted(vals.items()))"
```

| **仅年**（`YYYY`） | **26** | 只填年份 |
| **非标准** | **9 处 / 去重 8 个形态** | 见下表 |
| 非空合计 | **54** | 19 + 26 + 9 |

**非标准形态全表（去重 8 个）**：

> ⇒ **结论（规格依据）**：生卒字段存量**本质是自由文本**（含**中文月日**、**Gramps 区间区间串** `BET EST`、**公元前负年**）。**任何「强制 ISO / 过滤非 ISO」的改动都会使历史数据无法编辑保存** ⇒ **① 的「不得强制 ISO、不得过滤」是硬约束**（§4 红线第 1 条）。**同一批值里「非标准少而形态各异」= 选择器必须允许「留空 / 手输兜底」**（§2-2）。

## 2. 规范 ①：生卒时间 = 自由文本 + 日期选择器「双方式」

### 2-1 文本框口径（**硬**）

1. **保持自由文本输入**：出生 / 死亡两个输入框**不得**强制 ISO、**不得**过滤、**不得**做输入期格式改写；**`trim` 之外不动值**（与现状 §1-1 的保存口径一致）。
2. **选择器写入的值也必须回落到「文本框的值」** —— 文本框是**唯一真源入口**：选择器选定后，**写入文本框**（§2-2），提交仍走文本框的既有装配（§1-1 的 `:2641` / `:2644`）。
3. **存量形态一律可编辑**（§1-3 的 54 处非空值，含 9 处非标准）—— 打开编辑器时**文本框原样显示存量值**，**选择器不参与、不报错**。

### 2-2 选择器口径（**新增控件 · 硬**）

1. **控件形态**：`<picker mode="date">` **或跨端等价物**（候选 = `@tdesign/uniapp` 的 `date-time-picker` / `picker`，见 §1-1；**实现选型由 Kong 定，本册只登记口径**）。
2. **写入格式**：选择器选中后，**写入 `YYYY-MM-DD`（ISO）文本**到对应的出生 / 死亡文本框。
3. **初值解析**（**选择器打开时的默认日期**）：
   - 文本框**已有可解析值** ⇒ **作为选择器初值**；
   - 文本框**不可解析**（如 `BET EST 2005 AND 2010` / 负年 `-568` / 中文月日 `3月13,1958`）⇒ **选择器留空**（**不得报错、不得清空文本框**）。
4. **「可解析」的判定口径** = **待裁**（§6-1）：至少须覆盖 `YYYY` 与 `YYYY-MM-DD`；**是否**接受 `YYYY-MM` / `YYYY-M-D` 由 Kevin / Kong 定。
5. **选择器不负责清空**：清空**一律靠文本框手删**（选择器**不得**提供「清空」语义，见 §2-4）。
6. **双端**：H5 与小程序**同一口径**（选择器在两端的呈现可不同，但**写入格式 / 初值 / 不清空**三条一致）。

### 2-3 后端口径：**不动**（**硬**）

- **`applyLifespan`（`lib/tree-write.js:121`）保持现状**：`String(..).trim()`、**不校验格式**（§1-1）。
- **本批不得给生卒字段新增任何格式校验 / 归一 / 白名单** —— 否则 §1-3 的存量非标准值**将无法编辑保存**（违反 §4 红线第 1 条）。

### 2-4 清空口径

- **清空 = 文本框手动删空**（保存后按既有「空串」形态落库）。
- **选择器不提供「清空」按钮**（本册按 Kevin 拍定「清空仍靠文本框手删」登记；**是否为生卒字段另加「清空」按钮 = 待裁**，§6-2）。

## 3. 规范 ②：居住地 `start_year` = 固定四位 + 前端「真拦住」

### 3-1 语义（**不变 · 逐字冻结**）

- 契约 v3 F1/F3 **一字不改**：`start_year` 为**字符串**（`''` 或 `'1960'`）；**非空必须 `^\d{4}$` 且 `1000 <= N <= 2100`**；非法 ⇒ **400**（文案逐字见 `docs/person-places.spec.md` §20-3）。
- **只填年份也算一条有内容**（既有口径不变）。
- **出生地 `birth_place` 不加 `start_year`**（§20-2）**不变**。
- **既有默认色 / 上限 9 条 / 顺序即展示 / 计费 F7 / 白名单 F8** 一律不变。

### 3-2 前端受控输入口径（**硬 · 本批新增**）

1. **输入端即拦截**（区别于现状的「提交前预校」）：输入框 `@input` 阶段**过滤非数字字符** + **截断至 4 位**，使**非法长度 / 非法字符进不了表单状态**。
2. **建议形态**（**实现选型由 Kong 定**）：`type="text"` + `inputmode="numeric"`（数字键盘、且**不被 `<input type=number>` 的语义吞掉**），或**保留 `type="number"` 但手动过滤**；**「真拦住」= 双端一致**。
3. **受控值仍为字符串**（同 §3-1；**不得转成数字**）。
4. **保留字符面**：过滤后**只允许 `\d`**；**空串 = 未填**（放行，不算错误）。
5. **后端既有校验（§1-2）保持为最终裁决**（前端「真拦」**不替代**后端 400；后端 `assertStartYears` / `assertStartYearNotAfterDeath` **本批不改**）。

### 3-3 小程序端同步（**硬**）

- 小程序端**同一口径**：**过滤非数字 + 截断至 4 位**。
- **不得只改 H5 不改小程序**（两端**行为须一致**）；**这属于 §5「两产物重打」的判据之一**。
