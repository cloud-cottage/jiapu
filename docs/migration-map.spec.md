## 1. 数据推导口径（**树级迁徙总览；纯函数，零 IO、零请求**）

> 本节口径**全部为「规格要求」**（模块 `frontend/src/business/migration-map.ts` 成文时点**不存在**）；**唯一「实测」** = 演示真源 `ji_23395_01` 的聚合复核（见 §1-7）。

### 1-1 起点

- **起点码 = 树 `origin_code`**（`GET /tree/` 或 `tree-meta.trees.<tree_id>.origin_code`；空串 = 无起点）。
- **起点码从「节点」中剔除**，但**保留其人数**（见 §1-5）：起点在地图上**单独以「起点金」`#C9A227` 渲染**，不与迁徙节点混列。
- 起点码为**空串** ⇒ 无起点：**不臆造**（地图不画起点；见 §4 空态口径）。

### 1-2 节点 = 全树成员地点码聚合

- 对全树每个 person，收集其**三个来源**的 `origin_code`：
  1. `birth_place.origin_code`（读响应 = `profile.birth.place_code`）；
  2. `residence_places[].origin_code`（**多条**）；
  3. `death_place.origin_code`（读响应 = `profile.death.place_code`）。
- **收面（范围）**：**严格三来源**——**不得**纳入 `note` 纯文本、**不得**纳入 `origin`（树发源地展示串）、**不得**纳入任何 free-text 字段（**Q3=A**：无码文本不参与定位）。

### 1-3 去重与计数（**同一人的多个字段命中同一码只计 1 人**）

- 对**每个 person** 先把三来源收集到的码放**集合**去重（`Set`）⇒ **同一人同一码只贡献 1**。
- 节点人数 = **命中该码的去重后人数**（不是字段命中次数）。
- **空码不参与**：`''`（空串）、`undefined`、非法形态一律**跳过**（既不计数、也不报错）。
- **同一人命中多个不同码** ⇒ 该人**在每个码各计 1**（这是「人地点聚合」而非「人唯一归属」的既定语义；与 Q2=A「节点 = 全树成员地点码聚合」一致）。**本册不引入「主地点」判定。**

### 1-4 排序（**人数降序 → 码升序 tie-break**）

> 🚫 **本节「节点按人数排序」口径已作废（2026-10-05，取代者 §10「世 + 波次分组」）** —— **原行原文保留如下**（§0-4）。**「人数降序 → 码升序」在现行口径下只保留一处用途**：**主居地波**的选取（§10-2，非起点站点中人数最多者，并列取码升序第一个）。

- **排序键 = 人数降序**；**人数相同 → `origin_code` 升序**（字符串比较）作为 **tie-break**。
- 起点码不参与节点排序（§1-1）；**起点人数单独出参**（见 §1-5）。

### 1-5 起点码的处置（**从节点中剔除，但保留其人数**）

- 起点码**从节点数组中剔除**（避免「起点」与「迁徙节点」重复渲染）。
- **保留其人数**：出参须单独给出**起点人数**（= 若把起点码作为普通节点时应有的人数；**不受剔除动作影响**）。
- 剔除动作**不改变**任何其它节点的人数。

### 1-6 无码记录：计数与样本串上限

- **计数**：全树 person 的**无码**地点记录（`birth_place.note` / `residence_places[].note` / 及同类文本）**只统计条数与样本**，**不参与地图定位**（**Q3=A**）。
- **展示形态** = 「**另有文字记载 N 处**」清单（见 §3-2）；**禁止做伪地理编码 / 名称模糊匹配**。
- **样本串上限**：清单最多列 **K = 5** 条样本串（**定稿（2026-10-05 · Zang 裁定）：K = 5** —— 与已落地 `TEXT_ONLY_SAMPLE_LIMIT = 5` 一致；理由 = **仅作示意清单、5 条不撑爆 UI**）。**原「K 未定 → 登记为待办、须回问 Zang」已作废**（原字保留 · §0-4）。
- **计数口径**：**「处」= 记录条数**（同一人的同一字段命中只算 1 条）；**不去重文本内容**（同名文本出现多次 ⇒ 计多条）—— 与节点计数（§1-3，按人去重）**是两套口径**，**不得互相套用**。

- **非法形态不收集**（**不得**为 9 位码 / 非 6 位形态编造 6 位码；承 `docs/geo-origin.spec.md` §1-2 / §13-2 直筒子市剔除口径）。
- **省级 / 市级补齐是「集合闭包」**，不是「每码都生成三个分片」—— 补的是**去重后的集合**。

### 2-3 缺失 adcode 的降级（**不报错、只降级**）

- 若某码在产物中**缺分片** ⇒ **不抛错、不空白屏**：该码的几何**不渲染**，但**其余码照常渲染**。
- 缺失码**仍参与数据聚合**（§1 的口径与地图几何**解耦**）：即「人数统计照旧、地图上无该边界」。
- **降级不得触发任何网络请求**（**Q1=B** 的离线零请求不变式；**禁止**运行时回退到在线地图 API）。

### 2-4 前端消费口径（**零请求**）

- **不变式**：地图渲染与边界加载**不得发起任何网络请求**（**Q1=B**）；**不得**在运行期 `fetch` / `XHR` / `uni.request` 取边界或底图。
- **形态（规格要求）**：构建期静态引入 + `inflateBase64ToUtf8` 还原（同 `docs/geo-origin.spec.md` §5-4R 的形态纪律）。
- **反例登记（不得照抄）**：`frontend/src/business/api.ts` 以 `fetch('/static/tree-meta.json')` **运行时取静态件**是**既有反例**，**不是本册允许的形态**。

### 2-5 边界管线单测（**必须注册 · 未注册 = 假绿**）
