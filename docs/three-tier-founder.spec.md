## 1. 第一原则（Kevin 2026-10-12 逐字拍定）

### 1-1 原话照录（逐字，不得改写）

> 「**我们是要允许用户在自建家族的时候，无需认祖就自建根节点的。这个规则要写好，避免后续再次出现无根节点的家族。**」

### 1-2 拆解：两条**正交**规则（本册第一原则）

| # | 规则 | 内容 |
|---|---|---|
| **甲** | **自建根节点合法** | 家谱允许**不认祖**、**自己就是根**。树无上层镜像指针 ≠ 缺陷：家族树始祖 `external_*` 全空（v2 真身态）或祖谱无顶端镜像段（未认祖世本）均为**合法稳态**。**认祖 = 额外挂一条上层镜像指针**（`external_link_type='founder'`），是可选项、增强项，不是义务。 |
| **乙** | **始祖登记必写** | **每棵树落库必须登记始祖三件套**（`founder_handle` + `founder_gramps_id` + `founder_name`，落 `tree_meta` 档）。这是防「无根家族」的**硬闸**：所有建树路径**缺一整单失败不落库**。 |

- **正交声明（硬）**：甲与乙**互不前提、互不推定** —— 自建根节点（未认祖）**同样必须**完成三件套登记；完成三件套登记**不等于**已认祖。一句话：**防呆闸的是「未登记始祖」，不是「未认祖」**。任何把「未认祖」当缺陷处理、或把「已登记」当「已认祖」读的实现，均违反本条。
- **防再犯目标**：Kevin 拍定本原则的目的 = **避免后续再次出现无根节点的家族**；落点 = R2 落库硬闸（事前）+ R3 常驻巡检（事后）。

## 2. 术语与三件套

### 2-1 三层与 kind

| kind | 树 | 认祖方向（认祖发生时） | 权威 |
|---|---|---|---|
| `'master'` | 中华世本 `zhonghua` | ——（顶层，无认祖对象） | `docs/clan-tree.spec.md` §1–§2 |
| `'clan'` | 祖谱（按姓 / 支系，可多个） | 始祖认 `master`（顶端镜像段）；被 `family` 认 | 同上 |
| `'family'`（缺省） | 普通家族树 | 始祖认 `clan`；**禁止直挂 master** | 同上 §3-2 |

### 2-2 始祖登记三件套（R1 的登记对象）

| 字段 | 落点 | 语义 |
|---|---|---|
| `founder_handle` | `tree_meta` 档 | 始祖节点 handle（读侧一切以 founder 为根的推导首选入口） |
| `founder_gramps_id` | `tree_meta` 档 | 始祖编号（存储口径见 `docs/id-system.spec.md` §9；回退反查用） |
| `founder_name` | `tree_meta` 档 | 始祖名（登记名；占位名形态见 §6-4） |

- **legacy `founder_gramps_id`** = 树 JSON **顶层**的同名字段（存量形态：部分树仅树 JSON 内有它而 `tree_meta` 档缺 `founder_handle`）。自本册起其地位由 **R1** 定义（仅读侧回退）。
- **master（`zhonghua`）免登**：世本无「本树始祖登记」语义（其世系链自身即根），三件套闸不适用。

### 2-3 「无根家族」缺陷定义（本册防的对象）

**「无根节点的家族」= 树存在而 `tree_meta` 档无任何始祖登记（三件套缺失或全空），导致一切以 founder 为根的读侧推导失效**（迁徙地图世代 BFS 无根 ⇒ 全树人员无世代 ⇒ 按「无世数者不入站点」全丢，地图退化为「起点 · 0 人」；文谱世系序首选级尽空）。

- 读侧推断回退（`docs/wenpu.spec.md` §26-1 **W-17** 级 ③④⑤、迁徙地图根回退）是**不改真源的兜底**，**不能替代** R2 的落库登记 —— **推断 ≠ 登记**。
- 与「自建根节点」（§1-2 甲）严格区分：自建根 = **有登记、无上层镜像**；无根家族 = **无登记**。前者合法，后者是缺陷。

## 4. R0 —— 自建根节点合法（规则甲落条）

1. **合法态定义**：以下形态均为**合法稳态**，不是缺陷、不是待修项、不产生告警、不进任何异常 UI 态：
   - 家族树（`kind='family'`）始祖 = **真身**（`external_*` 全空，承 `docs/founder-attach.spec.md` §9-2/§9-4 v2 口径：未挂载可自填真身）；
   - 祖谱（`kind='clan'`）未认祖世本（无顶端镜像段；`docs/clan-tree.spec.md` §5「该祖谱未认祖世本」提示 = **信息性文案**，非异常态）。
2. **认祖 = 可选增强**：认祖动作 = 给始祖**额外挂**一条上层镜像指针（`external_link_type='founder'`）。认祖发生时，目标层级约束照旧：家族树认祖 target 只能是 `kind='clan'`、祖谱认祖 target 只能是 `kind='master'`、**禁止直挂 master**（`docs/clan-tree.spec.md` §3-2）；申请制 / 直接挂载 / 解除等原语一律以 `docs/founder-attach.spec.md` 为准，本册不重述。
3. **正交（重申，硬）**：R0 与 R2 互不前提（§1-2）。**任何路径不得以「先认祖」作为登记始祖的前提，也不得以「已登记始祖」推导「已认祖」。**
4. **与防呆闸的关系**：R2 / R3 的判据对象是**登记齐不齐**，与**认没认祖**无关。UI 与后端不得出现「未认祖 ⇒ 阻断建树 / 报警 / 标记异常」的逻辑。

## 5. R1 —— 单一真源

1. **`tree_meta` 档三件套 = 唯一权威**：`founder_handle` / `founder_gramps_id` / `founder_name` 的登记、变更、修复一律以 `tree_meta` 档为准。
2. **树 JSON 内 legacy `founder_gramps_id` 仅作读侧回退**：形态先例 = 迁徙地图根口径「根 = `tree_meta` `founder_handle`（回退 `founder_gramps_id`）」（`docs/migration-map.spec.md` §10）与文谱 W-17 级 ②（`docs/wenpu.spec.md` §26-1）。回退**只读不写**。
3. **写路径一律写 `tree_meta`**：建树、迁移（立支 / 汇宗）、认祖涉及的 founder 登记写面、修复，一律落 `tree_meta` 档；**不得以「只写树 JSON」代替 `tree_meta` 登记**。树 JSON legacy 字段是否随写由实现批按本条核对（现存随写先例 = `docs/branch-clan-ops.spec.md` §5-2 立支字段表）。
4. **不一致处置**：读侧以 `tree_meta` 为准；差异形态（典型 = 「树 JSON 有 legacy `founder_gramps_id` 而 `tree_meta` 缺 `founder_handle`」）由 **R3 巡检**报警。修复一律走「**先备份、后登记前后值**」体例（先例 = `docs/PENDING_DEPLOY.md` §67-1④ / §67-5 追记），**本册不设自动改写**。
